# Геометрия окна и панелей: как работает и что изменено

Версия документа — после правки 2.7.5. Разделы 2–3 приведены к принятым
решениям; раздел 1 — к фактическому коду; в конце «Принятые решения», чек-лист
прогонов и открытые вопросы.

## 1. Как это устроено сейчас (фактический код)

### Режим чтения
- Окно шириной `W`. Слева — оглавление `toc_w` (`TOC_WIDTH` = 240, минимум
  `TOC_MIN_WIDTH` = 120), справа — превью (остаток).
- Колонка превью центрируется `theme.side_margin(width)` до `MEASURE` = 1300 px
  через `viewport().setContentsMargins` (инвариант 2).

### Вход в правку (`DocumentView._enter_edit` → `_resize_for_edit`)
1. Запоминается ширина превью **до** добавления редактора:
   `_preview_width = max(browser.width(), MIN_COLUMN)`, `MIN_COLUMN` = 420.
2. Всегда сохраняется `window._view_geometry = saveGeometry()` (QByteArray, для
   персиста, инвариант 14) и `self._pre_edit_rect = QRect(window.geometry())`
   (для живого выхода).
3. Если окно `isMaximized()` или `isFullScreen()` — **resize не делается**
   (редактор вписывается в текущую ширину), `_edit_resized = False`.
4. Иначе целевая ширина:
   - `editor_cap = editor_cap_width(ratio)` — ширина редактора, дающая ровно
     `ratio` при превью `MEASURE` (`= ratio/(1-ratio) * MEASURE`, с клампами).
   - `cap = toc_w + handles + MEASURE + editor_cap` (B2 — потолок роста).
   - `desired = toc_w + handles + _preview_width + editor_cap`.
   - `target = min(desired, cap, screen_right − x)`, где `screen_right` — правая
     граница `availableGeometry()` экрана `window.screen()` (таскбар учтён);
     если `w > cap`, то `target = w` (уже шире потолка — не сужаем).
   - `target = max(target, MIN_WINDOW_WIDTH)`.
   - `window.setGeometry(x, y, target, h)` — **x/y не меняются**, растёт только
     правый край; `_edit_resized = True`.
5. `_relayout` раскладывает панели; ширина редактора берётся из доли:
   `editor_w = editor_width(avail − toc_w, ratio)`.

### Раскладка (`viewer.layout_panes`)
- Принимает **ширину** редактора (не долю) и остаётся чистой политикой уступок:
  TOC → редактор (`EDITOR_MIN` = 360, затем `EDITOR_HARD` = 220) → превью
  (`PREVIEW_HARD` = 260). Долю в ширину превращает `editor_width` (B3), которую
  вызывает `_relayout`.

### Выход из правки (`DocumentView._leave_edit` → `_restore_after_edit`)
- Если окно **реально ресайзилось** при входе (`_edit_resized`) и сейчас **не**
  maximized/fullscreen — `window.setGeometry(self._pre_edit_rect)` (тот же x/y/w/h,
  не `restoreGeometry`).
- Если окно не ресайзилось, или сейчас maximized/fullscreen (было при входе или
  развернули во время правки) — состояние не трогается. Правило детерминировано.
- `_view_geometry` сбрасывается; персист делает `closeEvent`.

### Доля сплиттера (`_on_splitter_moved`)
- Пользовательский драг редактора пишет `QSettings("editor_ratio") =
  editor/(editor+preview)` (кламп 0.05…0.95) и `self._editor_ratio`.
- `_editor_ratio` читается в `DocumentView.__init__` (по умолчанию `EDITOR_RATIO`).

### Персист
- `MainWindow.closeEvent`: закрытие в правке → в `QSettings("geometry")` идёт
  `_view_geometry` (до-правочная), инвариант 14 — без изменений.
- Старт приложения: `restoreGeometry(QSettings("geometry"))` — без изменений.

## 2. Проблема A — принято и реализовано

Правила (реализованы в `_resize_for_edit` / `_restore_after_edit`):
1. `x/y` не меняются никогда; двигается только правый край.
2. Живой enter/leave — через `setGeometry(x, y, w, h)`; `saveGeometry`/
   `restoreGeometry` только для персиста между запусками.
3. `target = min(desired, cap, screen_right − x)`, `screen_right` — правый край
   `availableGeometry()` экрана `window.screen()`.
4. Нижний кламп `MIN_WINDOW_WIDTH`; при нехватке места уступает `layout_panes`.
5. `isMaximized()`/`isFullScreen()` при входе — окно не ресайзится; на выходе
   состояние не трогается. Развернули во время правки — выход не разворачивает/
   не сворачивает.

## 3. Проблема B — принято и реализовано (B3 + B2; B1/B4 отклонены)

- **B3:** вместо абсолютной ширины хранится доля `editor/(editor+preview)` с
  клампами `EDITOR_MIN`/`EDITOR_MAX`/`PREVIEW_HARD`. Доля применяется при входе
  в правку и при первом показе; ручной драг перезаписывает долю; при live-ресайзе
  окна доля не пересчитывается.
- **B2:** окно в правке не растёт шире `cap = toc_w + editor_w + MEASURE + handles`.
  Если окно в чтении уже шире `cap` — при входе оно **не сужается**.
- Согласование: `editor_w = clamp(ratio*(W − toc_w − handles), EDITOR_MIN, EDITOR_MAX)`;
  при `W = cap` пропорция равна `ratio`.
- **B1** (доля ширины вместо фиксированной) не понадобился: B3 уже доля.
- **B4** (DPI) отклонён: логические пиксели Qt учитывают масштаб Windows.

## 4. Принятые решения

- **A1–A5** — как в разделе 2 (анкер по левому краю, `setGeometry`, `availableGeometry`,
  no-op при maximized/fullscreen, детерминированный случай «развернули в правке»).
- **B3 + B2**, `B1`/`B4` не используются.
- Новые константы (`theme.py`):
  - `EDITOR_RATIO = 0.30` — доля редактора в области превью+редактор по умолчанию.
    Обоснование: при `MEASURE` = 1300 даёт редактор ≈ 557 px — близко к прежнему
    `EDITOR_PREF` = 520 на 27", но одинаково на 34".
  - `EDITOR_MAX = 960` — редактор не шире этого даже на ультравайде.
  - `MIN_WINDOW_WIDTH = TOC_MIN_WIDTH + PREVIEW_HARD + EDITOR_HARD + SPLIT_HANDLE*2`
    (= 628) — нижний кламп целевой ширины.
  - `EDITOR_PREF = 520` оставлен как fallback/совместимость.
- **`layout_panes` не менялся по сигнатуре:** остаётся чистой политикой уступок по
  ширине; доля (B3) применяется уровнем выше (`editor_width`). Так сохранены
  проверенные тесты уступок. Это осознанное отклонение от буквы плана (там
  `layout_panes` в списке правок) — отмечено в открытых вопросах.

## 5. Чек-лист прогонов

Проверено автоматически (`tools/edit_check.py`, секция «window geometry»,
`MDVIEWER_TEST_SCREEN=secondary`):

- [x] 10× вход/выход на плавающем окне: `x/y/width` не меняются.
- [x] Максимизация → вход (без resize) → выход: окно остаётся maximized.
- [x] Вход обычным → максимизация в правке → выход: остаётся maximized.
- [x] `editor_cap_width(r)` при превью `MEASURE` даёт долю `r` (±2 px).
- [x] `editor_width` клампится в `EDITOR_MIN`/`EDITOR_MAX`.
- [x] Ручной драг сплиттера сохраняет `editor_ratio`; новая вьюха читает его.
- [x] Инвариант 14 (закрытие в правке → до-правочная геометрия) — прежний
      `closeEvent`, регресс не затронут.
- [x] У правого края экрана: `target = screen_right − x` (рост ≤ 1 px, за экран не
      выходит) — см. лог `geo_probe` (x не сдвигается).
- [x] Окно на границе мониторов: `window.screen()` = экран с наибольшим
      перекрытием (проверено: окно −800…1200 → экран `U1`).

**Не проверено автоматически:**

- [ ] Aero Snap (Win+←/→): реальный snap-жест не эмулировался. Ожидание:
      `setGeometry(x, y, target, h)` сохраняет x, но Windows может выйти из snap
      при программном ресайзе — **проверить вручную**.
- [ ] Разные масштабы Windows (100/125 %) на двух мониторах: DPI-переходы при
      ресайзе не эмулировались. Логика в логических пикселях Qt, но поведение
      переезда между мониторами с разным масштабом — вручную.
- [ ] 27" vs 34" «вживую» (доля в cap-режиме ±1–2 px): проверено арифметически
      (`editor_cap_width`), не на реальном втором мониторе с другой шириной.

## 6. Открытые вопросы (не додумывать)

1. **`EDITOR_RATIO = 0.30`** и **`EDITOR_MAX = 960`** — ок как значения по
   умолчанию, или хотите другие?
2. **`layout_panes` оставлен без изменения сигнатуры** (доля применяется в
   `editor_width`/`_relayout`). Если нужен строго «layout_panes принимает долю» —
   переделаю, но это переписывание проверенных тестов уступок.
3. **Перенос окна на другой монитор во время правки:** сейчас выход
   восстанавливает до-правочный прямоугольник (окно возвращается). Если хотите
   «оставить как есть» — поменяем.
4. **Aero Snap** — подтвердите вживую (плавающее / Win+← / Win+→): x не должен
   сдвигаться; если сдвигается — пришлёте, добавлю обход.
